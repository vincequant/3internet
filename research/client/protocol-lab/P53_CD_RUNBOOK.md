# C 隐藏要素 / D 只读部队面板 / A–C 验收开关

所有新开关默认关闭。本轮只交付离线候选与部署，不进房、不点火，不在旧局启用。先读 `P52_UI_RUNBOOK.md`；A/B/C 的原有实现和 849B P52 payload 未改。

## 一键切换

管理 Mac 双击 `p53_ui_control.command`。菜单显示每个元素的实际入口字节状态；输入一个编号只切换该项，`p 编号`只列计划，`q`退出。也可以在远端 `shadow/` 目录执行：

```bash
source ./_env.sh
"$WINE" "$P32" tools/p53_ui_control.py --action check
"$WINE" "$P32" tools/p53_ui_control.py --action plan --element map-trap-fire
# 下列两条只供新房逐项验收时使用，本轮没有执行：
"$WINE" "$P32" tools/p53_ui_control.py --action on --element map-trap-fire
"$WINE" "$P32" tools/p53_ui_control.py --action off --element map-trap-fire
```

每个进程使用 `logs/ui-switches/<WinePID>-<creation FILETIME>/` 下的两份独立状态文件。控制器同时绑定 PID、creation、完整 EXE 路径、shadow prefix、SANPK SHA、payload SHA 和原始/预期补丁字节。变化不匹配即停止；不接管未知补丁。锁文件包含控制器 PID，不自动删疑似陈旧锁；先核对对应控制器已结束再保留副本并移走锁。

`check` / `plan` 只以 `0x410 QUERY_INFORMATION|VM_READ` 打开目标，不分配洞穴、不写进程、不暂停线程。真正切换以 `0x438` 打开，暂停并核查目标线程后事务写入、读回；不创建目标线程。每次仅切一个元素，回执追加到 `switches.jsonl`。不加入 `arm_now.sh`。

### A 和原有 C

复用原有 17 项：`panel-create`；`stat-12c` 至 `stat-132`；`cards-init/update`；`map-tiles`、`map-unit-sight/detail`、`map-city-detail/skin`、`map-site-detail`、`map-marker-detail`。这些项的作用、写入范围和回滚语义仍按 P52 手册。

`panel-create` 要在新进程原生创建对局面板前安装。撤销只恢复创建入口的 P51 封印；已创建的原生控件留给原生窗口析构，不在活局删对象。其他数值/卡牌更新需逐项启用，不能把“创建控件”计为全部 A 已通过。

### B

盟军私聊是定向投递，保留 P52 结论。原生已收到的公开/私聊可正常显示；没有“复制未投递私聊”的开关。B 验收必须由有权参与的原发言人把风夜明确列入收件人；未投递不等于本端掉包。

### C 扩展的五个独立开关

| 开关 | 掩码 | 对象 vtable | 绘制替换 |
|---|---:|---|---|
| map-trap-fire | 1 | 50a0f0 火计 | 4afc5c |
| map-trap-rock | 2 | 50a1a8 落石 | 4afc5c |
| map-trap-pit | 4 | 50a260 陷阱 | 4afc5c |
| map-unit-sprites | 8 | RECON 的全部 12 类，含运输/游荡部队 | 4afc5c |
| map-site-sprites | 16 | 507e10/507ee8/507fc0 生产设施 | 4afc5c |

这是同一个绘制 CALL 的按类路由，五个位独立组合。32 个不可变入口表示所有组合；切换一项只改变 CALL 所指入口，不写游戏配置位。关闭最后一项，CALL 恢复原始 `ff506085c0`。其余四项不随单项回滚消失；RX 洞穴直到进程退出才回收。

原版位图绘制 `4afbad→4afc5c` 调图形对象 `vtable+60`；实体位图包装器 `4490d2` / `4491e5` 继续查询实体 `+70` / `+74`。替代仅针对这两个已核实包装器和列出的实体类；其他控件仍调用原方法。保留先前图像存在/裁剪门、原生 `flags & 0xa0000000` 禁用位、后续色深与 blit 分支。没有全局修改实体谓词，也没有填满势力视野位图。

陷阱 `483859` 对敌方走 `468724` 探测位；单位 `476bfc/476ca5` 同时检查视野与 `unit+0d` 低四位为 1 的隐藏分支。单位开关放开全部单位图像，涵盖伏兵；不把 raw_1d/1e 当伏兵标志。城关在此图像门原本已通过，不提供冗余城关开关。

**原生命中路径 `4afd49` 和 hover 的过滤保留。** C 显示出的敌方对象不会因此自动变成可下令对象；查属性用下方独立 D 窗口。仅证明已有本地实体及位图能通过这层绘制；不存在的对象不能凭空生成。图层、缩放、缓存/图像创建、是否已在观察端收到敌方陷阱都待新房目视/样本验证。

## D：点图查阅

管理 Mac 双击 `p53_unit_inspector.command`；它用 macOS `open` 启动远端 `tools/P53UnitInspector.app`，为 Wine 提供图形会话。直接 SSH 裸跑 Wine 在当前机器可能出现 `nodrv_CreateWindow`，不能用它判断面板代码无效。

窗口初始停止查阅。点「开启点图查阅」或 `Ctrl+Shift+I` 后，独立半透明查阅层覆盖绑定游戏的地图客户区。点击部队的落脚格显示完整已知字段；同格多部队再次点击轮换。此层接住左右/中键、双击和滚轮，不向游戏转发；停止查阅后再使用原版地图平移/缩放。刷新按钮只重读当前对象，坐标/身份已变则要求重新点击。关闭窗口就是 D 的回滚，不需要恢复任何游戏字节。

已显示：类型/ID/势力/坐标，兵数/兵粮布局值，剩余移动/兵装度，三名武将的姓名/字/五维/带兵/技能原掩码/状态/所在城/肖像 ID，指令原值及参数；未定 `+1d/+1e` 只标未定。缺武将/名称不补造。数值语义未完成新局画面对照，面板明确标注。

投影直接移植 `4986dd` 与精确菱形命中 `498591`，读 `doc+f22..f2e` 的尺寸/缩放，减 `view+54/+58` 相机原点，再用 Win32 ClientToScreen 定位查阅层；不依赖 `selected_unit`，不点选敌方。支持的四组缩放/奇偶行/斜边已与原 x86 对照，实际 DPI/图层仍需验收。

**面板改数值（2026-10-19 新增，仅风夜本机）**：点选部队后，窗口顶部一行可选字段（兵力/兵粮/士气/训练/武将统率/武将武力/智力/政治/魅力）、填数值、按「写入（仅本机）」；写入前验证对象仍是指定类（部队 vtable / 武将 vtable+ID），按原生上下限夹紧（士气运输兵≤50、武将 0–255），VirtualProtectEx 写入后回读并记录 before/after，可按「还原上一笔」还原。改武将统率/武力即改部队面板第三行「统武」= 统率+武力。写入只落在本机影子进程；是否经结算上报真实局沿用 P54 待验路线，不在此面板宣称。

目标读取只以 `0x410` 打开；写入时才另开一个 `0x1F0FFF` 句柄且只对本进程 PID。窗口/控件属于独立 Python 进程。不导入注入器的写执行入口、不调用游戏函数/同步事件或网络 API。停用时不轮询；启用时 250ms 只读窗口/几何字段，点击时才遍历部队/陷阱并读取三名武将。对象列表双读、对象身份与相机复核；不宣称整局原子快照。PID/creation 命名互斥量防止同一对象开多个查阅层。观察 JSONL 保存在 `shadow/logs/p53-inspector-*`。

## 验证与限制

`test_p53_hidden_draw` 执行原版绘制、原生命中与实际候选 x86，覆盖三类位图包装器/18 种实体、五个掩码互不串开、原禁用位、世界字段未改、共享谓词原字节与回滚。菱形命中与原 x86 按四组缩放/斜边/边界对照。`test_p53_unit_data` 覆盖错误链表/类型、对象消失/移动/复用、镜头改变、同格与缺武将。

合成 Win32 窗口证明查阅层实际 WindowFromPoint 命中、HTCLIENT、EDIT READONLY、点击只触发本端属性快照、底层合成地图零点击、停用后层隐藏。它没有打开 SANPK；不是活局验收。当前 Wine 的 PrintWindow 返回全黑图，Mac 区域截图也失败；黑图按失败证据保存，不作为画面验收。真实画面与 lag/RX/崩溃全部按 `P53_LIVE_ACCEPTANCE.md` 留待新房。

Mac 源码与远端工具逐文件白名单/备份/SHA 部署。原生 Windows 未实机验证；未改 Hub 发行包、游戏 EXE/DLL、存档、驻留驱动或正常启动脚本。
