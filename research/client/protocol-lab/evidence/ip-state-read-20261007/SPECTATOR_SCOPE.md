# 仅凭房主 IP、无玩家席位观战：范围修正与静态核对

2026-10-07 用户明确排除房主运行 Hub，也排除开局前小号作为玩家加入。目标仅为：等待玩家期间拿到 IP，作为不占玩家席位的接收者，在开局后接收对局状态。

此前 direct UDP 与 NetHook 定向搜房均在开局后执行，不能当作本目标的决定性失败，也未建立中继注册正向对照。不再据搜房无回应断言所有网络同步都不可能。

本轮仅静态读取原版 KOEINM.dll，无网络输入或游戏操作。核对 NetMsg_SendData 调用链：0x10002160 -> 0x10001be0 -> 0x100023a0 -> 0x10004b60（主机分支）-> 0x100064e0，向主机线程发消息 8；线程 0x10006750 的对应分支 0x10006851 -> 0x10006e40 -> 0x10005a90。0x10005a90 对群发调用 0x10005250；对单目标先在 0x10004330 查找成员，不存在则返回失败。

0x10005250 为发送路径：读取网络对象 +0x43bc 已连接成员数量，按 +0x43b8 的成员槽表（每项 0x164 字节）构建接收地址，再逐项发送。该路径没有把先前的房间查询者作为独立观战订阅者保存。结论限定为本次追踪的标准 SendData 路径，不是对全部游戏 EXE、NetHook、中继服务或断线重连能力的穷尽证明。

由此：仅提前查询 IP 不会自动获得标准对局同步流。目前没有已验证的不占玩家席位旁观会话。若某条合法协议可把旁观者纳入接收集合且不增加玩家席位，仍需独立证明；未做该动态实验。不能声称已经可以，也不应把当前证据扩大为绝对不可能。

已剔除的方案不再作为本需求的后续路线。当前游戏保持运行，无加入或状态修改。
