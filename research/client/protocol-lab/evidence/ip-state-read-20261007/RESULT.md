## 结论

当前未通过 IP 取得对局状态。确认游戏已经进入小地图、同一房主进程仍使用 10.128.163.42:7777。普通 UDP 搜房与原版 DLL 定向搜房均未收到回应；不能声称网络观战已实现，也不能声称一切协议路径都不可能。

## 分开的证据来源

1. **房主电脑只读内存与窗口**：VKQUANT-COM，已运行的 prefix-sikarugir10，kwankwan，Wine PID 664，SGZWLB，is_host=1，主机标识 176202538，端口字段 7777。窗口出现小地图。此来源用于核对目标与状态，不是 IP 网络读取成功证据。
2. **跨 Mac 直接 UDP**：VKQUANT 向指定 10.128.163.42:7777 发送一份原版搜房使用的四字节网络序应用标识 78731（0001338b），3 秒超时，无响应。私有 IP 非公网直连地址；没有测更多端口或扫描网络。
3. **原版 NetHook/Koeinm 定向查询**：VKQUANT-COM 上独立 32 位 Python 进程，共享房主 Wine prefix，目标仅 10.128.163.42:7777。仅实验进程的兼容版本临时设为 Windows 8.1，以满足历史已验证 NetHook 初始化条件。start_rc=0、search_rc=0、reply_count=0，unconfirmed_empty。没有独立证明该实验进程取得有效中继注册，因此不能把无响应全部归因为游戏拒绝。DLL 返回 0 也不代表网络可达。

## 搜房停止回应的代码依据

- NetMsg_EnableJoinSession（0x10002070）->0x10001a00->0x10004c10，将参数写入网络对象 +0x8414。
- 当前主机实测 +0x8410=1、+0x8414=0。
- SearchSession 响应函数 0x10007d30 在 +0x8414 为零时跳到返回路径，故即使正常搜索包到达，也不会通过此函数回复房间记录。
- 这说明本局当前关闭加入/搜索回复。未修改开关或内存，未验证在已关闭加入状态下还能合法接收同步的旁观角色。
- 搜房响应本身是房间名、房主、人数等，不是城市、武将、部队完整状态。
