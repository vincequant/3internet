# 隐形加入实测 — 2026-10-07

## 结论

使用用户指定的本机主号 VK（筑基期）及其正常大厅会话，独立调用原版 Koeinm / NetHook 网络接口，成功连接用户自有的 kwankwan 测试房间。但是，仅完成网络加入、没有运行游戏层握手，就已被房主登记进八个玩家记录中的第 2 个席位。因此，当前普通网络加入路径未实现“不占席位的隐形小号”。没有验证开局后观战或 Hub 状态读取；不能将这次连接成功称为观战成功，也不能据此证明所有其他协议路径绝无可能。

## 实测证据

- 房主：VKQUANT-COM，SANPK Wine PID 2052，房间 SGZWLB，网络地址 10.128.163.42，成员 ID 176202538。端口字段 7777，应用标识 78731。此处仅称原版接口观察到的网络地址，未独立证明它是公网地址或何种虚拟网络地址。
- 客户端：本机原版大厅正常登录、进入电信1（备用），用户手动启动游戏；游戏选择中显示 SGZWLB[kwankwan]。原版网络接口返回客户端地址 10.228.84.151，成员 ID 182736023，与正在运行的主号客户端只读字段一致。
- 原版 `_NetMsg_OpenSession@20` 返回 0；`_NetMsg_IsConnected@0` 返回 1。35 秒及 90 秒测试均保持连接，随后正常调用 ExitSession / End。历史日志分别保存为 `successful-35s-main-transport-join.jsonl` 与 `successful-90s-main-transport-join.jsonl`。
- 最后一次加入前，房主网络成员数为 1；玩家记录 slot 0 为房主 ID，其余七条 network_id 都是 0。见 `host-slots-baseline.txt`。
- 最后一次加入期间，房主网络成员数为 2，新增主号 ID 182736023；SANPK 玩家记录 slot 1 的 network_id 同时变为 182736023。见 `host-slots-during-join.jsonl`，两项读取退出码均为 0。读取通过游戏路径、EXE SHA256、Doc/Core 虚表绑定，只使用查询与 ReadProcessMemory。
- 房主玩家名控件为自绘 AfxWnd42s，WM_GETTEXT 不能取得其屏幕文字；远端指定窗口截图也失败。因此本次没有可用的房主屏幕截图，未声称肉眼确认显示的姓名。席位登记本身已经与“不占席位”的要求不符。

## 静态证据

`host-ui-notification-dispatch.txt` 中，SANPK 0x46565b 解码网络通知；类型 1 在等待阶段进入 0x4658c0，选择八个玩家记录中的空位，0x4658f4 写入来客成员 ID，随后调用 0x46ea53 更新玩家界面。对局阶段的对应分支调用 RefuseUser。该路径与本次玩家记录变化一致；这不是所有可能协议路径的穷尽证明。

## 早期阻塞与恢复

已配置小号 vinceost 的原版大厅返回“用户已经登录”，因此未强制登录或绕过认证。用户后来指定使用本机主号，沿其正常登录会话完成上述实验。远端小号临时 LaunchAgent 与临时凭据文件已清理。早期失败与修正保留在原日志中，不作为最终可行性结论。

## 边界与清理

只针对用户自有的测试房间；未写运行中游戏内存、修改游戏 EXE、覆盖存档、扫描网络或绕过服务器认证。测试客户端按原版接口正常退出，退出后的房主网络成员数恢复为 1，第 2 个玩家席位的 network_id 恢复为 0；见 `host-slots-after-exit.jsonl`。临时客户端 EXE 和仅针对它的 Wine AppDefaults 注册表项已清理。本机主号大厅与两台机器的原有游戏保持打开；主号临时启动服务 KeepAlive=false，没有自动登录或自动重试。

此次仅研究证据与临时实验脚本，无 Hub/TK 功能变更或发布，无 Windows 实测。
