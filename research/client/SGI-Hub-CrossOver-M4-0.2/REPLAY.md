# 整局记录与全景回放

采集桥一旦拿到本局第一个有效快照，就会自动建档，不依赖 Hub 窗口或回放窗口是否打开。一局一档，不循环覆盖，不自动删除旧对局。现有闪退 FlightRecorder 仍只服务诊断，不能当整局录像。

## 独立启动

- Mac：双击 `Start-Replay.command`，或 Wine 导航里「打开历史回放」。
- Windows：双击 `Start-Replay.cmd`。
- 命令行：`python -B app/panorama_replay.py`；演示加 `--demo`。

回放只读本地档案，**不会**启动采集桥或游戏。关闭 Hub 不影响正在写的档案。

## 档案位置

默认 `game-archives/`（可用环境变量 `SGI_HUB_REPLAY` 改路径）。现在只保留开局判定为玩家 1v1 / 2v2 / 3v3 的整局；22 国前奏和电脑局不建档。玩家局要等同盟锁定后才开始写盘。回放列表不放电脑局和模拟演示档。

## 回放操作

播放、暂停、从头、速度、上一帧/下一帧、拖动时间轴。逐格 = 真实采集帧，不是补出来的格子。可按季度、部队位移段和缺口跳转。地图缩放、拖动、搜城、势力筛选、跟随所选部队与现有全景相同。

「视觉插值（非事实）」默认关闭；打开后只平滑已有部队的坐标，不改兵数、归属或对象集合，不跨缺口，也不提前显示下一帧新部队。

点各军首都后，右侧先打开「指令」看该国建设/训练/录用/出征，「该势力部队」列出该国全部出征部队，再才是本视野部队和交战部队。内政（建设/训练/录用）归到该年春第一回。夏秋冬以及春的后两回按军事回合拆开，一季三回，标「第1/2/3回合」。`[` / `]` 按回跳，左下列表跟着滚。不再写季 0–3，也不堆部队位移段。交战页顶部列出各势力总战力（出征部队攻击系数之和，不是实伤）。指令由相邻帧变化推断，不是引擎指令日志。得城前后十几帧内，该城上新出现的练兵所/牧场/弓工坊算随城转入，不记新建；营比城归属早一帧露出来也算转入。播放、拖动时间轴只改地图帧，指令账在停住后分段补齐。打开档案复用已写好的 index，不整份解压。静止帧不重画底图和叠层。开局收束前的 22 势力消失和建国并不记入指令。部队 ID 消失后复用且兵种/归属不同，不会强行连成一条线。

档案格式版本 2：增量按实体列表下标保存，允许重复将领 ID；顶层字段整份复写或删除，不再靠短白名单。

只读分析接口见 `WAR-QUERY.md`。查询结果不含视觉插值。运行中的采集桥未切到本版前，不要把连续战局分析当成已可靠。

## 证据含义

- **事实**：直接采到的状态，例如内政录用待确认。
- **观察变化**：相邻帧之间的可见差异。
- **推断**：由变化判成建设、训练、出征等，不能当成引擎指令日志。
- **未知**：缺口、中途才开始记录，或没有采到。无数据 ≠ 没有下令。

军事阶段没有单独的游戏枚举。界面写的是「本帧是否观察到部队位移」，未采集的中间格不会补造成事实。部队 ID 消失后再出现且兵种/归属不同，不会强行串成一条轨迹。

## 中途采集与封存

中途才接到第一帧会写「从此处开始记录」。游戏进程消失、同进程开新局，或连续五分钟局面无采集变化（忽略每次采样自带的时间戳），会封存旧档；查看端断网、单次采样失败只记缺口，不假装正常结束。磁盘满或写入失败会在状态里标明，不阻塞采集。

## 1.1.276：训练研究数据与证据来源

回放侧栏明确标示“事实/推断/观察变化”。查询返回`training_capture`，逐势力记录原始指令覆盖；当前原始指令流未捕获，`raw_instruction_count=null`不能当成0指令。状态差异以及原有`command=true`不能直接作动作训练标签。

本机可创建不参与发布的`training-capture.local.json`：

```json
{"enabled":true,"observation_mode":"omniscient","scenario":null,"computer":"unknown","ruleset_id":null,"ruleset_confirmed":false}
```

采集桥下次启动读取此配置，把同一份已采到的状态另存`training-archives/`，保留电脑局、短试验和失败记录；不会改变普通玩家回放保留规则，也不会多读游戏。`/health`和`/api/state`的`training_archive`可核对是否启用。规则和等级必须来自本局证据，未知就保留未知；开启录制不是训练数据验收。

纯离线工具（工作目录为Hub根目录）：

```sh
python bridge/replay_training.py export ARCHIVE NEW_OUTPUT --first 1 --last 25 --max-frames 25
python bridge/replay_training.py supplement AUDITED_DATASET ARCHIVE
```

导出只读原档，缺失rounds缓存也不会回写。输出只有前状态features/后状态targets、状态变化和来源，动作、因果、奖励和终局均不推造。默认最多250帧，显式上限不超过1000；真实档案和模拟夹具的来源标记保留，输出目录必须不存在。

`supplement`新建独立`training-evidence-v1`附件，不改历史帧。输入必须先由AI研究转移工具完成语义审核；Hub额外核对SHA、进程/版本、归属和结算回执关系。附件只显示当前游标之前已经核验的结果，缺失/变化证据会隔离。它不是全势力原始指令流，也不会修补原episode动作日志。附件目前使用本机绝对证据路径，跨机迁移必须重新打包与核验。

源码升级不会自动升级正在运行的旧采集器；实际状态版本与配置启动状态分别核对。发布白名单不含本机训练配置、存档或研究数据。

## 回滚

发布失败时停止本项目 Hub/采集桥/回放（不停游戏），执行 `python publish.py rollback TARGET BACKUP`。

## 1.1.293：修改使用按势力处理

快捷面板的加时、施舍、增强训练使用后，列表与回放提示注明我方势力使用过外挂。完整回放保留；仅该势力本局行动训练样本排除，对方势力行动保留参考。对方受交互影响仍可能有偏差，不自动认证其干净、专家或原始指令状态。

标记附在`modification-evidence-v1/`，绑定原始帧与档案身份，复制或分享档案时须一起保留。训练导出的manifest及每条观测元数据提供`training_force_policy.excluded_training_force_ids`；原始状态仍完整保存作上下文参考，审核标记不放入决策前features。`bridge/replay_training.py export ARCHIVE OUTPUT --force-id N`拒绝已标记我方，允许对方参考导出；未知／损坏标记阻止行动证据导入，原回放仍保留。不从状态差分补造任何动作标签。

## 1.1.324：旧回放攻击值兼容

完整技能数据的陆上部队显示 `[当前攻击指数/满士气攻击指数]`，弓兵只计算射击。1.1.320 等旧采集器没有保存技能原值；这类回放若仍有当帧的旧参考值，显示 `旧参考124·技能未存`。旧参考保持原来的计算尺度，不是新攻击指数，也不能当成当前/满士气数对。不会用网站技能或后续帧补造该帧的原始技能；无旧参考时仍显示未知。新采集器会保留技能原值，即使档案压缩移除 raw_hex，仍可重算。
