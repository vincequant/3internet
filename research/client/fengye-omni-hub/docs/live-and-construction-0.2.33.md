# 0.2.33：自動讀取、原版勢力頁與原生建設位置

## 開局後勢力空白的根因與修正

正式 `run.py` 路徑順序使 `bridge/command_effects.py` 先於 Hub 根目錄載入。新增指令效果模組與原模組同名，導致 `_binding` ImportError；原來根目錄優先的測試沒有重現正式啟動環境。Hub 專用模組已改名為 `fengye_command_effects.py`，以子程序回歸測試覆蓋正式載入順序，原版橋接模組保持獨立。

戰場與外部指令繼續共享背景唯讀採集，每3秒自動重試；兩頁移除手動讀取入口。單筆顯示錯誤、時間線持續錯誤、非法日期都不會讓後續採集停下。完整例外只進本機有限大小的 `data/runtime-errors.log`，畫面顯示等待／過期／重試，不印本機路徑或 Python traceback。

右上角依實際 shadow 快照顯示「實時採集・本次讀取 N 幀」及讀取時間；重複樣本不增加，舊樣本不回退，同局重啟頁面不冒稱歷史總幀數。這是本次已觀測數量，沒有聲稱回放已寫入檔案。

## 原版勢力情報及對比

直接重掛原版 widgets 與 renderers，包括手牌原圖、信望值、庫存、訓練、城池、武將、外交、內政等分頁，以及原版勢力比較欄位。兩頁使用同一份已驗來源的原始快照複本，不另啟真人端讀取器。原版 widgets 的 native parent 仍在 workspace，因此切頁時須 lift/lower；已對映測試檢查最上層實際命中原 widget，原生截圖也確認可見。

內政原始指令尚非全勢力完整輸入流。畫面保留「僅顯示已捕獲的記錄；空白不代表沒有下令」，不由狀態差分造出原始命令。

## 為何原來的可建位置不對

舊版把 Collector 的 column-major 地形表用 row-major 索引查詢，讀到另一個位置；另外只允許地形2、使用方形半徑4，也與原生 UI 不同。現改用一個共享純規則檔 `_p60_construction_rules.py`，供主地圖與入隊前 Wine helper 使用，包含：

- 原始索引 `x * height + y`，原生交錯距離與城池半徑3；關隘不產生新候選。
- 設施的地形0／1／2與鄰城關排除；陷阱另允許7至19類地形，並核對控制勢力、四鄰交戰部隊與逐城陷阱數。
- 城池原始旗標、動態佔用、同格部隊、資源，以及 Hub 已排隊／待結果格。
- 按原始城池容器順序選 linked city，與原版點選 handler 一致。

只讀 Collector 包裝器在同一次 capture 的 page cache 內補讀 tile+0xc／+0xe，輸出控制勢力及物件種類兩張 signed16動態表，不寫遊戲記憶體，不沿用靜態地形快取冒充動態狀態。實測20402格兩表均完整、0未知；同一真實樣本的燕／代、四種類型共8組運算及 helper 呼叫結果一致。詳細靜態證據及限制見 [原生規則](construction-native-rule-0.2.33.md)、[當局量化](construction-live-0.2.33.json)。這是原碼規則重建與唯讀樣本核對，並非實送建築成功證明。

## 選址畫面

在原作地形／城池／兵種圖上以半透明淡藍填色標出候選格，保留地形及 sprites；滑鼠所在可選格用白框，選定後用金框。未高亮位置不再於滑鼠移動時逐格顯示「不可選／未知」。點格只選取，明確按「確認位置並加入隊列」才入隊；入隊後立即保留格子，避免重複建設。畫面提醒資源及額度仍需再核對，最新讀取與入隊前檢查不同時刻，狀態可能改變。

原版同類設施增建是另一分支，目前送出器沒有驗證增建，既有設施不列為新增建築候選，避免疊出物件。原版本機 UI 的全域待發陷阱計數尚未完整採集，保留未知，不用各城 pending 和或0代填；位置高亮不保證該本機 UI 的全域規劃額度已通過。人口不足／徵兵額滿是原版可確認繼續的警告，沒有錯當成地形禁止。
