# 风夜假名池 + 撞名防护（2026-10-18 定）

## 一、名池用途

1. **防撞名**：进房瞬间读我方收到的成员行，若名字已存在（真玩家在房）→ 立即撤（不发 D8），痕迹＝一行进出；
2. **像本地人**：优先使用"大厅里真实出现过的名字风格"；
3. **可轮换**：同一晚连开数局时换名，降低被记住的概率。

## 二、候选名池（`backend/fengye_names.json` 建议结构）

```json
{
  "preferred": ["待秋至"],
  "reserve": ["风夜", "小白", "夜航船", "秋风渡", "望江月", "半盏灯"],
  "observed": [],
  "taken": [],
  "notes": "observed = 大厅/房间实际出现过的名字（采集后填充）；taken = 已知被占用的名字（撞名防护用）"
}
```

- **preferred**：默认首选（当前=待秋至）；
- **reserve**：备用（轮换用；风格与本地玩家接近、不带"测试/程序"字样）；
- **observed**：从大厅/房间实际采集到的真玩家名（**采集后自动追加**）；
- **taken**：已知被占 → 撞名防护直接避开；`observed` 会自动并入这里。

## 三、采集来源（不必进房）

| 来源 | 能得到什么 | 代价 |
|---|---|---|
| **大厅房间列表**（直连带线面板/Hub 查房） | 每个房的**房主名**（房间标题里，如 `SGZWLB[丁满]`）+ 人数 | 零（只读列表） |
| **进房一瞬间的中继名册 + 房内成员行广播** | **全名单**（谁在里面） | 进房可见（~1 秒窗口），撞名即撤 |
| 历史记录（我们的 Hub 会话/查房缓存） | 以往出现过的房主与成员名 | 零 |

**采集动作（开发项）**：Hub 房间监控每次刷新时，把"房主名 + 已知成员名"追加进 `observed`（去重）。
**多线2 大厅**：需要一次 **多线2 的登入+查房**（用直连面板的线路切换即可，或由我跑查房链）→ 结果自动进 `observed`。

## 四、撞名防护流程（进房即校验，1 秒内可撤）

1. 进房成功 → 立刻读**本进程**成员行（复用 `p32_app_rows_read.py`，pid=自己）；
2. 若候选名 ∈ 房内名单 → **abort**：房间层离场（0x21 广播）+ 不注入 D8；切换到 `reserve` 的下一个名字重试（最多 2 次）；
3. 若干净 → 走快链藏身（D8 提前、守卫后置），窗口压到 ~3–5 秒；
4. 全过程留日志（候选名/命中/撤离/重试），并入 Hub 会话证据。
