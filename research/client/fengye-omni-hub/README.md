# 風夜情報台 0.2.32

目前操作以本節為準。下方折疊內容保留舊版工程與實驗紀錄；其中的乘數、舊指令下拉、施捨、米交易及「回執即完成」流程均不是現行操作方式。

## 外部指令：按下即入隊，進度一直可見

選擇「玩家・勢力」後，使用七個指令按鍵：**步兵、騎兵、弓兵、兵營、馬房、弓房、陷阱**。

- 練兵：按一下對應兵種，立即加入隊列；不必再按另一個送出鍵。固定值由面板處理，下方同步顯示讀到的累積訓練值及金。
- 建設：先選建設種類，直接在主頁原作大地圖選址，不另開視窗或列出大量城池按鈕。所選勢力所有城池的可建位置一起標出；重疊格按最近城池及穩定城池編號歸屬。選址時隊列暫收合以放大地圖，確認入隊後自動展開。綠框只描邊、保留地形；單擊只選格，最後按 **「確認位置並加入隊列」** 才加入。已有物件、已排隊或尚未核實的建設位置不重複使用。
- 進度：每筆指令保留同一列與操作時間，可切換「處理中」「已完成」「已撤回／未完成」，點選列查看經過。以玩家用語顯示「等下一個內政回合」「已下令，等待變化」及實際前後數值，玩家、勢力和建設城池皆顯示可核實名稱。
- 撤回：選中尚未發送的指令，按 **「撤回選中的未處理指令」**。已開始代送的指令不會冒稱已撤回；不明結果也不會自動重送。

**本機回執只表示本機送出流程有回報。只有重新讀到實際訓練值增加或相符的新建設物件，才移到「已完成」。** 未能核實時保留在處理中並說明原因。同一兵種的前筆效果尚未確認時，下一筆先等待，避免把一次增幅算成兩筆完成。

三個隊列分頁只顯示當局指令。以 Collector 的真實進程建立時間、核心、版本、劇本與名單等事實綁定；無局識別的舊版記錄與其他局一律不顯示，也不自動匯入舊發送檔。歷史保留本機 `data/command-history.json`，不進發行包；重啟不重播。相同真實身分跨面板重啟可繼續查閱；Collector 尚無獨立局 ID，同一進程／核心／劇本／名單完全重用仍有識別限制。

## 戰場：原全景地圖與自動讀取

戰場沿用全知情報的原全景地圖渲染器，呈現城池、原作兵種圖形、旗幟、補給線、格線及可核實的血量／士氣等細節，保留縮放、拖曳／WASD 平移與獨立大地圖。縮放控制使用深色文字；移除對手狀態與上方對手篩選、城池搜尋定位、可產兵閾值。陷阱固定顯示，僅保留「文字」勾選框。

戰場與外部指令預設每 **3 秒**自動讀取風夜自己的狀態，單次讀取未結束前不另起重疊請求。資料失效會保留上次畫面並標示狀態，不把舊值當即時；「立即讀取」只供手動加快一次更新。兩頁共用快取與讀取，不回退到丁滿、風雲或其他真人客戶端。回放模式不讀即時來源，也不提供實際代送。

本版另有獨立的深墨青／金色風夜圖標及 macOS ICNS，只更新情報台，不改遊戲或 Wine 啟動器圖標。

## 風夜操控台

1. 選擇線路，點「登入風夜大廳」。使用採集端已配置的風夜帳號及原版中繼取得自己的會話；不啟動遊戲。
2. 大廳就緒後，每 15 秒 SearchSession 取得房間列表，顯示房間、房主、虛擬 IP 及人數，也可手動更新。未收到回覆顯示未確認，不當成零房間。
3. 選一個房間，選擇或輸入「進房暱稱」，點「進入所選房間」。暱稱限 GBK 可表示、30 位元組，不接受空白或控制字元。只接受 60 秒內實際查房回覆中的房間，不允許直接指定任意 IP。
4. 面板顯示 OpenSession 原始回傳、本端／房主 ID、目標虛擬 IP、遊戲口、中繼 A／B 口及收包／釋放數。這是 DLL 連接握手，**不是玩家準備完成或開局成功**；本版不自動發送任何指令、不參與同步、不發戰局指令。進入可能佔據房間席位；開局前流程見下節。
5. 「退出房間」調用正常 ExitSession，返回大廳監控；「停止大廳」結束本 Hub 自己的會話。退出回執驗證本端 IsConnected，不把 BOOL 型回傳 1 當成錯誤，也不宣稱主機席位已釋放。

## 長局旁聽（0.1.8）

- 摘席後可長時間旁聽：會話上限 24 小時；只要本視窗開著（5 秒輪詢維持心跳），探針會持續接收。視窗關閉後探針於 90 秒內自動收尾。
- 摘席後主按鈕變為**「收線（結束旁聽）」**（同一「停止大廳」操作）：一次性退出本端會話，失敗不重試；大廳狀態列同時顯示「旁聽中 時長」與收包／釋放計數。
- 研究鏈長局（p42/p43 編排器 `--long-run`，23 小時聆聽窗／24 小時保活）：在「發言與回執」頁的**「風夜收線（令探針正常退出）」**寫入一次性 hub-control stop；「旁聽回執」卡顯示旁聽剩餘時間、連線狀態、收包數、最後活動與收尾觀察是否已記錄；編排器在收線後保留 60 秒主機側收尾觀察（`post-exit-tail.json`）。

每條進退房請求先綁定會話、保留唯一 ID，再執行一次。等待回執或結果未知時不重發。視窗關閉後停止查房輪詢；本 Hub 啟動的探針在最多 90 秒內因視窗心跳到期正常收尾。

若採集端另有研究會話運行，復用唯一現有中繼查房，顯示「既有大廳中繼監控」；不重複登入、接管或終止別的會話。此時進退房按鈕停用，需原會話正常結束後才能啟動本 Hub 的獨立會話。

帳號和認證仍由採集端既有 P1／原版 loader 流程處理，不放入發行包或顯示握手通道。採集端需已配置 `~/sgi-protocol-lab-20260915`、Wine、32 位探針、P1／P39c2 loader 及 P28 接收模組。Mac／Windows 前端均經既有 SSH 連接採集端；此版未提供原生 Windows 採集代理。

## 開局前流程（cmd2 註冊／D8 摘席）

進房握手後可選兩步，各自一次性、需在對話框確認、失敗不重試：

- **幽靈註冊（cmd2 無特徵）**：以採集機器的名稱組 cmd2，先寫本端 `+8440=0`（seq0 免檢通道，p20 實證）再發送一次。房間名單會短暫出現一行無特徵成員；ACK 以本端序號推進為準（面板顯示）。
- **開局前摘席（D8）**：需已註冊且序號已推進、原生同步狀態=1（開局前）；經可靠通道（`0x4c80/0x4b60`）發送一次 D8（自身離場）。應用層席位行消失（房間會出現一行「（暱稱）从游戏中退出了」），**DLL 會話保持並繼續接收**。發送前先落 reservation，已摘席或未滿足條件一律拒絕。

兩步沿用研究鏈 P32／P33／P34 已驗證模組並綁定 Koeinm SHA（不符即拒絕）；採集端缺少任一指令模組時僅停用這兩步。房間行外觀、行消隱與「開局不等待」仍以另端觀測與實機驗收為準。**此流程尚未實機驗收**（採集端離線期間完成開發）。

## 開局後控制（0.2.15–0.2.19）

「風夜操控台」內含三個子分頁：房間監控／發言與回執／風雲・本機控制。本機控制提供風雲帳號直連登入、退出、強制關閉與**本機席位切換**；同頁另有「風夜・遠端勢力切換」盒（讀取風夜席位／切到 0–7／還原）。**席位表與按鈕只列可切換的玩家席（電腦／空席直接隱去）**；讀取失敗時按鈕全部放行，方便重試。

### 面板的標準流程（已內建）

1. 玩家在**軍事/結算階段**（任何非內政階段）把命令填好、按「送出」。
2. 面板在結算期把風夜席位切到目標勢力的席位（`shadow_force.sh switch N`）。
3. agent 的相位閘門在**下一個內政階段**開門，把命令送進遊戲的命令流。
4. 收到回執後自動把席位切回 slot 5（無勢力）。
5. 若按送出時剛好在內政階段，面板會先等本輪結束（最多 150 秒）再切，避免「切太晚」被丟。
