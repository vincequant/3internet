## 追加實驗三：讀呼叫點 → 我們的**呼叫約定（ABI）是錯的**

把 Koeinm 裡 `4c80/4b60` 的實際呼叫點（`0x100024b2`、`0x10002502`、`0x100024f0` 家族）讀出來：

```
; 例：0x100024b2（送出前）
lea  ecx, [esp+0x10]      ; 指向一個暫存區（不是 id！）
push ecx
push esi                  ; netobj
call 0x10004c80           ; ★ 兩個參數
add  esp, 4               ; 只清 4
push eax
push esi
call 0x10004b60           ; ★ 也是兩個參數（eax = 4c80 的回傳）
add  esp, 0x10            ; 清 16（含前一個呼叫留下的 4）

; 例：0x10002502
push 4                    ; len = 4
push eax                  ; 指向 4 bytes 的緩衝
push esi                  ; netobj
call 0x10004c80           ; ★ 三個參數
add  esp, 4
push eax
push esi
call 0x10004b60
add  esp, 0x10
```

**我們的 agent 只壓了 1 個參數給 4c80、清 4；4b60 壓 4 個參數、清 16。**
兩邊的參數數量與清理量都對不上 ⇒ `4c80` 回傳的「target」其實是垃圾，
`4b60` 收到的 body 長度/位置也不對 ⇒ 幀雖然上了線（tx +1），但內容不是合法 D8，主機自然不理。
