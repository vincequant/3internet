# P60-CRASH：一條畸形建設命令讓**全場三台客戶端同時 AV**（0x44C156）

日期：2026-10-19 22:17 ｜ 現場：同一局（190 年）｜ 全滅：丁滿 236、風雲 1204、風夜 1596

## 0. 一句話

**送出一條 `kind 18 / subtype 4`（建設）但 `actor=0、value(city)=0、operand=(0,0)` 的畸形命令**，
回合結算時三台客戶端**同一秒、同一個 EIP** 觸發 access violation 而全部退出：

```
exception 0xC0000005 (access violation)
EIP 0x44C156   cmpb $0x1, 0x83(%edi)      ← edi 無效
tick 455083787 / 455083789 / 455083823   （三台同一瞬間）
pid  236 (丁滿) / 1596 (風夜) / 1204 (風雲)
```

⇒ 這是使用者要的「讓對局崩潰／掉線的指令」的**第一個可重現候選**，
而且是**全場型**（送出後不是只影響某一台，而是主機結算 + 廣播批次讓所有客戶端一起死）。

## 1. 怎麼發生的（老實說：是我們自己的 bug）

那時我剛把 Hub 面板接上，`build_args()` 誤把參數從 job 頂層取（實際上參數在 `job['params']`），
於是實際送出的命令變成：

```
kind 18, subtype 4（建設）
operand = (0,0)      ← 原本要 (36,119)
actor   = 0          ← 原本要 2（孫堅）
value   = 0（city）  ← 原本要 42（柴桑）
extra   = 2000
```

回執 `rc=1`（傳輸層照收），但**內容是一條指向不存在城池/座標的建設**。
回合結算時：主機套用 → 自己 AV；廣播批次 → 另一台也 AV；藏身幽靈也在套用時 AV。

## 2. 判定與界線

* **成立**：畸形建設命令可以在回合結算時打死整場（含送出者自己）。
* **尚未分離**：三個變數（actor=0 / city=0 / xy=(0,0)）哪一個才是觸發點，還沒逐一測。
  最小嫌疑是 `city_id=0`（城池清單查不到 → 回傳 NULL → `0x44C156` 的 `edi` 解引用）。
* **附帶結論**：`0x44C156` 是「套用建設命令」路徑上的 NULL 檢查缺口，
  若要修（或要防止誤傷自己），這是第一個要補的點。
* **對「只打某一勢力」的意義**：目前這條是**全場武器**，不是精準武器。
  精準打法要另找「只被某一台客戶端處理、且該台會炸」的資料面（例如私聊/私有狀態、或該台的 UI 通知鏈）。

## 3. 立即處置（已做）

1. Hub 面板 `build_args()` 修好（參數從 `params` 取）。
2. 面板加上**前置驗證**：勢力必須在局、建設的城池必須屬於該勢力、座標必須在城 5 格內且不是城池格、
   人事必須有武將 id —— 這條畸形命令**不會再從面板送出去**。
3. 實驗室已重新一鍵拉起（新局），舊局證據保留。

## 5. 下一步（若要把它做成「按鍵」）

1. **分離變數**：分別測 city=0（xy 正常）、actor=0（city 正常）、xy=(0,0)（city 正常），
   找出最小觸發條件。每次一發、用新局、破壞性動作前報批。
2. **精準化**：找只影響單一客戶端的資料面（私聊、私有通知、UI 元素鏈），才可能有「踢掉某一家」的效果。
3. **防護**：若不想誤傷自己，先把 `0x44C156` 的 `edi` 空值檢查補上（記憶體補丁，不動 EXE）。
